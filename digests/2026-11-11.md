# Engineering Digest — 2026-11-11

Seven reads on invariants, transaction traps, and the metrics that mislead. The theme of the day: **measure what actually broke**.

## Distributed Systems

### 1. Engineering Correctness in Distributed Systems — Alex Chang
https://medium.com/@herefindalex/engineering-correctness-in-distributed-systems-33e2d9950dfb

Start from the invariants that must always hold, then choose consistency mechanisms and tests around them — a repeatable method for reasoning about timeouts, partial failures, and recovery before they become production behavior. For anyone designing cross-service workflows.

### 2. Don't Smooth the System — Kadir Atesoglu
https://atesoglu.medium.com/dont-smooth-the-system-dff81bef8286

Averages and clean dashboards can hide the very structure that explains why a system behaves the way it does — variability is often hidden state, not noise. A good prompt to ask what your observability is smoothing away.

## Java / Spring Boot

### 3. Spring Boot @Transactional: 12 Production Bugs That Senior Engineers Still Ship — Production War Stories
https://medium.com/engineering-playbook/spring-boot-transactional-12-production-bugs-that-senior-engineers-still-ship-58231c8bf2cd

Self-invocation, checked exceptions that commit, the rollback-only trap — twelve ways the annotation quietly does something other than what the author assumed, told through a payment that committed after an error. Essential for anyone reviewing Spring transaction code.

### 4. Passed Review, Failed in Prod: A 7-Part Series on the Spring Boot Bugs Nobody Catches — Md Jahid Hasan
https://medium.com/@jahid.csedu/passed-review-failed-in-prod-a-7-part-series-on-the-spring-boot-bugs-nobody-catches-c2f54e4c2286

A series built around one running example — a customer order engine — where each bug looks correct in review and only bites against a real database under load, starting with @Transactional rollback lies and LazyInitializationException. A good bookmark for the whole series.

## Cloud Infrastructure

### 5. Postmortem: Postgres failover in load test — Nyverra
https://blog.nyverra.com/posts/postmortem-postgres-failover-pdb-en

A capacity rehearsal pushed p95 to 8.4 seconds and triggered a CloudNativePG failover that then stuck mid-shutdown — the root cause was an HPA sized for CPU while each pod ate 1.2 GiB of memory. Honest, numbered, and a useful reminder that failover needs a rehearsal, not just a runbook.

## Applied AI / RAG

### 6. A Production RAG Pipeline, End to End — Yamraj Khadka
https://www.yamrajkhadka.com.np/writing/rag-pipeline

RAG in production is a data pipeline with a model attached: parsing, chunking, hybrid retrieval, reranking, citations, and two layers of evaluation — retrieval recall first, answer quality second. A clear end-to-end shape for anyone moving a RAG prototype toward real users.

### 7. The RAG Change That Looked Fine — Until Production Users Caught It — Prakash K
https://prakash888kpk.medium.com/the-rag-change-that-looked-fine-until-production-users-caught-it-ed7bb85819a6

A small chunk-size tweak passed CI and the demo, then quietly degraded retrieval for two weeks — nothing threw an exception, users noticed first. The fix: treat retrieval, grounding, and ingest trust as release properties gated in CI, not notebook confidence.
