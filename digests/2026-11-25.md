# Engineering Digest — 2026-11-25

Seven reads on the guarantees systems quietly break — and the patterns that hold them together. The theme of the day: **guarantees, traps, and honest evals**.

## Distributed Systems

### 1. Kafka Exactly-Once Semantics Explained: Spring Boot, Transactions & PostgreSQL — Engineering Unfiltered
https://medium.com/engineering-playbook/kafka-exactly-once-semantics-explained-spring-boot-transactions-postgresql-81ef79c322a9

Kafka's transactional guarantees stop at the broker boundary — your Postgres writes, payment calls, and emails are outside them. A clear map of at-most-once vs at-least-once vs exactly-once, and where idempotent consumers and the outbox pattern actually do the work. For anyone who has ever claimed "exactly once" in a design doc.

### 2. Transactional Outbox Pattern: Spring Boot, Kafka, PostgreSQL & CDC — Engineering Unfiltered
https://medium.com/engineering-playbook/transactional-outbox-pattern-spring-boot-kafka-postgresql-cdc-5be469f28877

The dual-write problem, solved the boring way: record the business change and the outgoing event in one Postgres transaction, then let a publisher or Debezium move it to Kafka. Covers polling vs CDC, SKIP LOCKED, ordering, and exactly-once semantics — the reference implementation for reliable event publishing in Spring Boot.

## Java / Spring Boot

### 3. The 4 AM Production Bug: 8 Jackson Serialization Traps in Spring Boot — Ankur
https://medium.com/engineering-playbook/the-4-am-production-bug-8-jackson-serialization-traps-in-spring-boot-e57c86570b16

Eight ways JSON serialization breaks a healthy-looking service at 4 AM — unreadable requests that never reach the controller, mismatched DTOs, date formats that work until someone sends one. Each trap comes with the evidence-first debugging path. For anyone who has chased a 400 that "shouldn't happen".

### 4. 35 Backend Engineering Mistakes That Even Senior Developers Make in Production — ProdRescue
https://medium.com/javarevisited/35-backend-engineering-mistakes-that-even-senior-developers-make-in-production-a421a493b19c

The mistakes that survive code review and tests: volatile where atomicity is needed, @Transactional wrapped around external API calls, virtual threads treated as unlimited concurrency, ConcurrentHashMap mistaken for a workflow lock. Thirty-five of them, each with the production consequence. A good pre-incident read for senior backend engineers.

## Cloud Infrastructure

### 5. AWS Cost Optimization: How to Build Scalable Cloud Infrastructure Without Overspending — AWS Builder Center
https://builder.aws.com/content/3MUoZVjOBRwX1gwn6TJfmdEmqbT/aws-cost-optimization-how-to-build-scalable-cloud-infrastructure-without-overspending

A practical AWS-side checklist published Nov 23: Cost Explorer and anomaly detection first, then right-sizing, S3 lifecycle tiers, pricing models, and removing the unused. Nothing exotic — the value is the order of operations, measure, analyze, optimize, monitor, repeat, as a habit rather than a one-off project.

### 6. The Kubernetes Autoscaler That Turned a Slow API Into a Production Outage — SYSTEM DESIGN
https://medium.com/javarevisited/the-kubernetes-autoscaler-that-turned-a-slow-api-into-a-production-outage-53e0c497f2f6

HPA scaled 8 replicas to 32 on a CPU signal while the real bottleneck was Postgres connections — each new pod opened 20 more, and throughput fell as replicas rose. A queueing-theory walkthrough of why CPU-based autoscaling misfires on I/O-bound services, and what metric to scale on instead. Essential for anyone running Spring Boot on Kubernetes.

## Applied AI / RAG

### 7. Production RAG: Evaluation, Security and Monitoring — AIDataCenter
https://aidatacenter.ai/insights/ai-agents-llms/production-rag-evaluation-security-monitoring-2026

A demo answers from memory; production answers from evidence — with permissions. Covers permission-aware retrieval, hybrid search, grounded and cited answers, prompt-injection defenses, and an eval dataset that separates retrieval failures from generation failures. For teams shipping RAG to real users with real access controls.
