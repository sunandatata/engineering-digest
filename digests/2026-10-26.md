# Engineering Digest — 2026-10-26

Six reads worth your time today. The theme of the day: **design for failure, measure before tuning**.

## Distributed Systems

### 1. PyTorch Conference 2026: Notes from an Infra Engineer — gengwg
https://gengwg.medium.com/pytorch-conference-2026-notes-from-an-infra-engineer-85c3e9a9f8cb

GPU infrastructure teams are now treating dead GPUs, flapping NICs, and lost hosts as normal operating conditions, not exceptions — training jobs keep going instead of falling back to an hour-old checkpoint. Worth reading for anyone running inference or training at scale, especially the notes on KV-aware routing nearly doubling throughput.

### 2. When AI Meets Distributed Systems: The Engineering Behind Every Prompt — Kandurravali
https://medium.com/@kandurravali/when-ai-meets-distributed-systems-the-engineering-behind-every-prompt-6e9310d10631

Reframes an AI request as a distributed transaction that happens to end with a model call, so familiar failure modes — cache invalidation, partial failures, backpressure, retry storms — explain most production AI unreliability. A useful mental model before reaching for a new model or prompt fix.

## Java / Spring Boot

### 3. Java Garbage Collection Tuning: G1GC vs ZGC and Why Your Spring Boot API Still Has High p99 Latency — The JVM Engineer
https://medium.com/engineering-playbook/java-garbage-collection-tuning-g1gc-vs-zgc-and-why-your-spring-boot-api-still-has-high-p99-latency-dafe6f7cbcb9

Before swapping collectors to chase p99 spikes, check whether the JVM actually paused those slow requests — in the example here, a row lock was the real culprit. For Spring Boot engineers tired of collector debates that skip measurement.

### 4. Spring Boot Redis Cache Problems: 7 Mistakes That Destroy Performance Under Heavy Traffic — The JVM Engineer
https://medium.com/engineering-playbook/spring-boot-redis-cache-problems-7-mistakes-that-destroy-performance-under-heavy-traffic-4aa6de7acb40

A cache that looks perfect in development can collapse in production when keys expire together, hot records skew traffic, and deployments invalidate entries — sending thousands of identical queries at Postgres at once. Practical checklist for anyone relying on @Cacheable under real load.

## Cloud Infrastructure

### 5. Post Incident Report: Oct 6, 2026 - Delays in pipelines, workflows, UI data, and notifications — CircleCI
https://discuss.circleci.com/t/post-incident-report-oct-6-2026-delays-in-pipelines-workflows-ui-data-and-notifications/54908

A maintenance process writing transaction logs faster than they could be archived slowly filled the database's log volume, while short-lived alerts that kept clearing on their own masked the trend until jobs started failing. A good lesson in recognizing a combination of alerts, not just each one in isolation.

## Applied AI / RAG

### 6. Asking Your RAG Model Where an Answer Came From Is Not an Audit — Igor Eduardo
https://medium.com/@igoreduardoai/asking-your-rag-model-where-an-answer-came-from-is-not-an-audit-896f1ed8d305

A new interpretability study found a model's self-reported source follows its internal answering state, not the document it was given — swapping the document after answering flipped none of the source reports. If you need provenance for a RAG system, you need it from the pipeline, not by asking the model.
