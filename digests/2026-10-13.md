# Engineering Digest — 2026-10-13

Six picks spanning incidents, edge runtimes, JVM internals, and production RAG. The theme of the day: **incidents, edge runtimes, RAG retrieval**.

## Distributed systems / Incident review

### 1. GitHub Actions and Hosted Runners degraded performance — Oct 5, 2026 — GitHub (postmortem.io)
https://postmortem.io/incidents/github--2026-10-05--actions-hosted-runners-datacenter-cloud-network-failure/

A partial networking failure between an on-prem datacenter region and cloud-hosted database and storage endpoints left 47% of workflow runs failing at peak. The writeup is a good case study in blast-radius containment: shifting traffic to healthy regions and adding compute capacity before root cause was fully understood. Worth reading for anyone who owns CI/CD reliability.

## Distributed systems / Edge compute

### 2. Cloudflare Bought Deno. You Have 12 Months. — Max Quimby (dev.to)
http://dev.to/max_quimby/cloudflare-bought-deno-you-have-12-months-13ie

Cloudflare bought Deno for celld, a small Rust binary that runs Workers and Durable Objects on your own servers using only an S3-compatible bucket as coordination. Each Durable Object gets its own SQLite database, with no control plane, consensus, or membership service. A sharp lesson in how removing coordination machinery beats optimizing it. For anyone designing multi-node systems or evaluating edge portability.

## Java / Spring Boot

### 3. JVM Performance Tuning for Spring Boot: GC, Heap, and Profiling — Marcelo Domingues (devdomain)
https://medium.com/devdomain/jvm-performance-tuning-for-spring-boot-gc-heap-and-profiling-46e800360f0b

A clear decision guide for the highest-leverage JVM tuning call you will make: throughput (Parallel), general purpose (G1), or sub-millisecond pauses on large heaps (ZGC). Practical details like why an aggressive MaxGCPauseMillis backfires and why generational ZGC is the preferred Java 21 option make this one to bookmark before your next Spring Boot production deployment.

### 4. Spring Boot Startup Time Optimization — springboot-kb
https://github.com/nguyen-mau-anh/springboot-kb/blob/HEAD/09.deployment/25-spring-boot-startup-time-optimization.md

A hierarchy of startup-time techniques ordered by impact versus cost, from JVM flags and AppCDS up through AOT processing to GraalVM native. The key insight is matching the technique to the workload: long-running services barely benefit, while Lambda SnapStart gets Java cold starts to roughly 300ms with one config change. Essential reference for scale-to-zero Spring Boot work.

## AI / RAG engineering

### 5. Building FinRAG: Architecture, Retrieval Engineering, and Lessons from 500+ Active Users — Amitsingh Chauhan
https://medium.com/@amitsinghchauhan1oa/building-finrag-architecture-retrieval-engineering-and-lessons-from-500-active-users-fdc5d4616709

Lessons from running a finance RAG assistant for 500+ users, and the headline finding matches production experience everywhere: 95% of wrong answers came from retrieval failures, not the model. Section-aware parsing, BM25 plus cross-encoder reranking, and a refusal protocol that builds user trust round out the takeaways. For teams hardening a RAG pipeline past demo stage.

## AI / Cloud operations

### 6. The $1.2M SRE Autoscaling Disaster: Why Autoregressive Agents Fail at Infrastructure Write Boundaries — Towards AI
https://pub.towardsai.net/the-1-2m-sre-autoscaling-disaster-why-autoregressive-agents-fail-at-infrastructure-write-8c45d16b7089?gi=873f7b20184f

An autonomous SRE agent mistook a PostgreSQL lock for a traffic surge and provisioned 400 GPU instances across three AWS regions, costing $1.24M over a weekend. The takeaway is architectural, not moral: prompt constraints are not a substitute for deterministic circuit breakers on infrastructure write paths. Required reading if you are wiring agents to scaling APIs.
