# Engineering Digest — 2026-11-12

Seven reads on the bottlenecks that move when you fix one. The theme of the day: **bottlenecks move, they don't disappear**.

## Distributed Systems

### 1. Design a Distributed Job Scheduler: The Failure Cases Senior Engineers Miss — Production War Stories
https://medium.com/engineering-playbook/design-a-distributed-job-scheduler-the-failure-cases-senior-engineers-miss-789d0206a2e4

A worker that loses its lease during a GC pause can resume later believing it still owns the job — the piece walks through why exactly-once is the wrong promise and how to make duplicate attempts identifiable and recoverable. For anyone building scheduled or background work.

### 2. Engineering an Enterprise E-Commerce Platform: SAGA Pattern, Kafka KRaft, and Zero-Downtime CI/CD — Tanu Tanbirul
https://medium.com/@tanu.tanbirul/engineering-an-enterprise-e-commerce-platform-saga-pattern-kafka-kraft-and-zero-downtime-ci-cd-7b52951b9a03

A concrete walkthrough of replacing 2PC with saga orchestration and compensating transactions, atomic inventory locks against overselling, and Kafka dead-letter topics — a working Spring Boot 3 and Kafka KRaft reference design for e-commerce backends.

## Java / Spring Boot

### 3. We Increased HikariCP From 20 to 100 Connections. PostgreSQL Got Five Times Slower — Devrim Ozcay
https://medium.com/engineering-playbook/we-increased-hikaricp-from-20-to-100-connections-postgresql-got-five-times-slower-d43733bcd88b

Raising the pool from 20 to 100 connections across 12 pods took p99 from about 400ms to over 2s — more connections just let more requests fight over resources that were already saturated. A clear case for sizing the pool to the database, not to the traffic.

### 4. We Enabled Java 21 Virtual Threads. PostgreSQL Became Our New Bottleneck — Software Engineering Knowledge
https://medium.com/engineering-playbook/we-enabled-java-21-virtual-threads-postgresql-became-our-new-bottleneck-b1f9926a9fd5

Virtual threads let the Spring Boot service accept far more concurrent requests — then HikariCP ran dry and checkout p99 went from 180ms to nearly 7s. A reminder that removing one bottleneck just exposes the next one downstream.

## Cloud Infrastructure

### 5. The migration that passed every check and still broke 140 websites — Kashif Manzer
http://dev.to/kashif_manzer/the-migration-that-passed-every-check-and-still-broke-140-websites-42fc

Buttondown moved custom domains to CloudFront, verified all 212 domains on its list, and still broke about 140 — the domains it had never verified were never on the list. A detective story about building migration checklists from DNS, not from the database.

## Applied AI / RAG

### 6. Building a RAG Pipeline for Semantic Code Search: A Developer Diary and Field Notes — JetBrains Blog
https://blog.jetbrains.com/ai/2026/11/building-a-rag-pipeline-for-semantic-code-search-a-developer-diary-and-field-notes-part-2/

Part 2 of JetBrains' account of building Air Context, their production RAG system for code search: storing millions of vectors so the index keeps up with Git, and retrieving the right ones in milliseconds. Six months of real trade-offs, not a tutorial.

### 7. Production Problems in RAG and How to Solve Them — Live Demo — Vishal Mysore
https://medium.com/@visrow/production-problems-in-rag-and-how-to-solve-them-live-demo-9e785d025ccb

Nine problems that show up after day one — one edit re-embedding the whole corpus, a crash leaving mixed versions, a model swap breaking similarity — each replayable in a browser lab. A practical checklist of standard data-engineering patterns applied to RAG.
