# Engineering Digest — 2026-10-18

Seven reads worth your time today. The theme of the day: **failure amplification, cost-aware platforms, RAG rigor**.

## Distributed Systems

### 1. Every Retry You Added Made the Outage Worse — Daniel Valev, DevOps.dev
https://blog.devops.dev/every-retry-you-added-made-the-outage-worse-f49e6437a8e3

Three service layers each retrying three times turn one failed query into 27 database calls — the author counts it with 120 lines of Python. A crisp case for a retry budget owned end-to-end instead of per-layer; for anyone who has ever added retries=3 and moved on.

### 2. A Senior Engineer Proposed Kafka. The Staff Engineer Asked for the Failure Model. — The JVM Engineer, Medium
https://medium.com/engineering-playbook/a-senior-engineer-proposed-kafka-the-staff-engineer-asked-for-the-failure-model-a1e680afdf02

A Kafka migration proposal that sailed through review — until someone asked what happens when reservation succeeds, payment fails, and the compensation event arrives twice. A sharp reminder that distributed-system reviews should start with the failure model, not throughput; useful for anyone proposing async workflows.

## Java / Spring Boot

### 3. Spring Boot Performance Tuning: 12 Production Problems Every Senior Java Engineer Should Know — Java in Production, Medium
https://medium.com/@devcommando/spring-boot-performance-tuning-12-production-problems-every-senior-java-engineer-should-know-9bd3e906d71a

Covers twelve real production failure modes — pool exhaustion, GC pauses, OOM kills — with the discipline of diagnosing the layer before touching anything. The central lesson: raising the Hikari pool or adding Redis without evidence can make things worse; for Spring engineers on call.

### 4. Building a Consistent Validation Layer in Spring Boot Without Leaking Framework Details — The Turtle Code, Medium
https://medium.com/@theturtlecode/building-a-consistent-validation-layer-in-spring-boot-without-leaking-framework-details-8d416cb3650c

Argues that validation errors are an API contract: stable identifiers, no controller class names or framework messages leaking to clients. A practical pattern for teams whose error shapes drift between endpoints; short and immediately applicable.

## Cloud Infrastructure

### 5. Every Kubernetes PR now tells us what it costs, and what it breaks — Medium
https://medium.com/@tabeed68/every-kubernetes-pr-now-tells-us-what-it-costs-and-what-it-breaks-8b9299010e63

One Python script makes every GitOps PR comment show the cost delta (OpenCost) and Kubescape security failures before merge. Includes hard-won lessons — pin your scanner, fail open on missing data, scope pipeline credentials read-only. For platform teams pushing FinOps and security left into code review.

## Applied AI / RAG

### 6. RAG Best Practices for 2026 — AgentFlare
https://agentflare.org/research/rag-best-practices-for-2026.html

Lays out RAG as a family of architectures with real numbers: naive RAG at $0.001-0.01/query vs agentic pipelines at $0.01-0.10 and 5s slower, plus example SLOs like p95 retrieval under 300ms. The recurring finding: tune retrieval (recall improved 50%+ with the same model) before touching the model; for teams sizing their pipeline.

### 7. How to Evaluate RAG Systems: The RAG Triad, Ragas, TruLens, and CI/CD Gates — TecWorms blog
http://tecworms.blogspot.com/2026/10/day-7-how-to-evaluate-rag-systems-rag.html

Shipping an embedding-model swap without an eval suite is a vibe check, this piece argues — and shows how to make evaluation versioned and build-blocking with the RAG triad (context relevance, groundedness, answer relevance) plus ACL leak tests. For anyone taking RAG past the demo stage.
