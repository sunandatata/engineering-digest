# Engineering Digest — 2026-10-10

Seven reads worth your time today. The theme of the day: **retries, storage, and hard production lessons**.

## Distributed Systems

### 1. How Uber Protects Against Retry Storms — Uber Engineering
https://www.uber.com/us/en/blog/protecting-against-retry-storms/

Uber's 'error ownership' retry middleware lets only the service that owns a failure retry, so propagated errors stop cascading instead of multiplying. Max retry-storm radius across user-facing APIs fell from 25 hops to 3, and one large degradation avoided an estimated 9.5M unnecessary retry requests. Essential reading if your service mesh's retries could become the next outage amplifier.

### 2. The Ground Beneath the Database — MongoDB Engineering
https://www.mongodb.com/company/blog/engineering/ground-beneath-database

The design story behind Atlas Infinite, MongoDB's disaggregated storage architecture: compute nodes hold no data, while consensus on every write moves into a shared Log Service, a Page Service keeps materialized pages warm per zone, and an Object Index Service over object storage is the durability floor. For distributed-storage builders tracking where compute/storage separation is headed.

### 3. From Chaos to Control: Addressing Shard Distribution Challenges in M3DB with Subclusters — Uber Engineering
https://www.uber.com/us/en/blog/from-chaos-to-control/

How Uber rebalances shards across M3DB (its distributed metrics store) without skewing the donor subcluster: a greedy algorithm simulates counterfactual per-node shard counts and always donates the shard whose removal leaves the subcluster most balanced. A clean, reusable rebalancing idea for anyone operating sharded stores.

## Java / Spring Boot

### 4. We Turned On Virtual Threads and Made Java Slower. Twice — The Concurrent Mind
https://medium.com/@kp9810113/we-turned-on-virtual-threads-and-made-java-slower-twice-a5eea625f529

A Spring Boot/Tomcat payment service enabled virtual threads and watched throughput drop ~40% with p99 latency tripling — synchronized blocks were pinning virtual threads to carrier threads. They rolled back, tried again, and hit it again. Read this before flipping the virtual-threads switch on your own service.

### 5. Replacing ThreadLocal with Scoped Values in Java 27: Production Patterns for 2026 — syuthd.com
https://www.syuthd.com/2026/10/replacing-threadlocal-with-scoped.html

ThreadLocal's per-thread hash tables become memory and GC liabilities under millions of virtual threads; Java 27's finalized Scoped Values offer an immutable, scope-bound alternative. Covers production migration patterns including bridging legacy SLF4J MDC and Spring Security context. For teams planning the Java 27 move.

## Cloud Infrastructure

### 6. The status page was green while apps crashed. The postmortem explains why. — slabb (dev.to)
https://dev.to/slabb/the-status-page-was-green-while-apps-crashed-the-postmortem-explains-why-5am3

A practitioner teardown of Google's Oct 2, 2026 Firebase postmortem: a stale config-flag cleanup on Sept 28 crashed iOS apps because the Analytics SDK never validated a nil flag name, while the dashboards stayed green the whole time because they rely on server-side health metrics. A sharp lesson in client-side observability for anyone shipping an SDK or mobile client.

## AI / RAG Engineering

### 7. The Vector That Lied About Its Dimensions — The Build
https://thebuild.com/blog/the-vector-that-lied-about-its-dimensions/

pgvector 0.8.7 fixes CVE-2026-103484, an out-of-bounds write in IVFFlat index builds where working arrays were sized from the column's type modifier but loops were bounded by each vector's own header — the third memory-safety CVE in its index-build code this year. Includes practical upgrade notes (installed package isn't enough; you must recycle backends still running the old library). Required reading if pgvector serves your RAG pipeline.
