# Engineering Digest — 2026-11-20

Six reads on what the November outage wave exposed, the Spring Boot traps that only show up in production, and the RAG stack as it actually stands in late 2026. The theme of the day: **outage waves, production traps, honest RAG**.

## Distributed Systems

### 1. The November 2026 Outage Wave, Explained: What Broke at Microsoft 365, the FAA, AWS, Chase, and United, and What Didn't Happen — Noah — Control Plane
https://dev.to/noahcontrolplane/the-november-2026-outage-wave-explained-what-broke-at-microsoft-365-the-faa-aws-chase-and-dop

Five major outages in five days, each with a different cause and none linked to a cyberattack: the piece lines up the timelines and mechanisms side by side, then distills the shared lesson — a fault in one widely used component spreads everywhere. Comes with a short checklist (remove single shared dependencies, run multi-region with live traffic, test failover, keep a break-glass sign-in) worth stealing for your own architecture review.

## Java/Spring Boot

### 2. Spring Boot in Production: Expert Level — Manuel Herrera
https://www.manu506.com/en/dev/articulos/spring-boot-in-production-expert-level

The production traps that pass every test: self-invocation bypassing proxies, transactions that can't roll back a payment call, scheduled jobs running on three instances at once, shutdowns that cut requests mid-flight. Every claim is backed by code compiled and tested against Spring Boot 4.1.2 on real Postgres. Read it before your first week in production, not after.

### 3. 12 Spring Boot Production Problems That Expose Engineers Who Only Know the Framework — SYSTEM DESIGN — ProdRescue
https://medium.com/engineering-playbook/12-spring-boot-production-problems-that-expose-engineers-who-only-know-the-framework-76dbc55322fc

A healthy dashboard, a green K8s status, and an API that went from 80ms to 12 seconds: the walkthrough starts from HikariCP pool exhaustion, a @Transactional throughput killer, and the N+1 queries your unit tests never catch, and lands on a diagnostic method rather than a bag of fixes. Good interview prep and better on-call prep.

## Cloud Infrastructure

### 4. Building a Cost-Aware AWS Architecture: Designing Cloud Infrastructure That Knows When to Scale Down — AWS Builder Center
https://builder.aws.com/content/3LuQDHIsD9whJsFXl8EWTWMCr9l/building-a-cost-aware-aws-architecture-designing-cloud-infrastructure-that-knows-when-to-scale-down

Cost optimization treated as architecture, not an afterthought: design around usage with scheduled scaling for dev environments, EventBridge plus Lambda automation, and S3 lifecycle policies, while keeping reliability and security in the frame. The useful part is the measurement list — utilization, idle spend, automation success rate — so you can tell whether the savings are real.

## Applied AI/RAG

### 5. RAG Pipelines for Platform Teams: Vector Stores, Chunking, and Evaluation — Yuval Glasman — Platform Monkey
https://platform-monkey.com/guides/rag-pipeline-platform-engineering

A full reference architecture on the verified late-2026 stack — Qdrant 1.20's native BM25, Cohere Embed 5, voyage-4, RAGAS 0.4 — with chunking strategy, hybrid retrieval, an eval harness wired into CI, complete K8s manifests, and cost math from live rate cards. The rare RAG guide that names exact versions and prices instead of hand-waving.

### 6. RAG in Production: Retrieval Is Data Engineering, Not a Prompt Trick — André Claudino
https://medium.com/@andrelgcclaudino/rag-in-production-retrieval-is-data-engineering-not-a-prompt-trick-d07c3defe223

Your answer can never be better than the retrieval that fed it: the piece argues retrieval quality is the ceiling, then works through chunking as a design decision, measuring Recall@K separately from generation, grounding checks at runtime, and gating deploys on a golden question set. For teams whose RAG demo works and whose production system quietly fails.
