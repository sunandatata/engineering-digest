# Engineering Digest — 2026-11-17

Today's picks: lessons from Microsoft's global outage, a cloud bill torn apart line by line, and RAG pipelines deliberately pushed until they break. The theme of the day: **outages, bills, and silent failures**.

## Distributed Systems

### 1. Microsoft's Global Outage: What Backend Engineers Can Learn About Building Resilient Systems — Sujith Raman S
https://medium.com/@sujithramans2020/microsofts-global-outage-what-backend-engineers-can-learn-about-building-resilient-systems-f4c1edb914fc

The Nov 12-13 outage took down Outlook, Teams, and SharePoint, and the write-up turns it into six concrete resilience lessons: blast-radius isolation, gradual rollouts, graceful degradation, circuit breakers, and rollback planning. A timely case study in why even the biggest platforms fail the same ways smaller ones do.

### 2. 70 Advanced Production Failures That Can Silently Corrupt Distributed Systems — Inside Backend Engineering
https://medium.com/engineering-playbook/70-advanced-production-failures-that-can-silently-corrupt-distributed-systems-63804d38dab9

A catalog of the failures that never page anyone: acknowledged PostgreSQL commits lost in failover, Kafka offsets committed before the transaction lands, Redis failovers dropping writes. Keep it as a reference for design reviews — the point is that a 200 response proves nothing about durability.

## Java/Spring Boot

### 3. Spring Boot Production Troubleshooting: 15 Real Failure Scenarios and Fixes (2026) — Systems at Scale
https://medium.com/engineering-playbook/spring-boot-production-troubleshooting-15-real-failure-scenarios-and-fixes-2026-be3efb955b71

Fifteen production scenarios with symptoms, diagnostics, and fixes: HikariCP exhaustion with a healthy database, p99 jumping from 180ms to 9 seconds, pods OOM-killed by unbounded concurrency. The recurring lesson is that the visible symptom is rarely the cause — trace the chain before restarting everything.

### 4. We Doubled Our Database Connections. The API Got Slower. Here's What We Missed — Devrim Ozcay
https://medium.com/javarevisited/we-doubled-our-database-connections-the-api-got-slower-heres-what-we-missed-0936de3e661b

Doubling the pool moved the bottleneck from HikariCP into PostgreSQL itself, where it was harder to see and more expensive to fix — p99 climbed while the pool looked fine. A clear explanation of why a connection is permission to submit work, not capacity to do it, and why the first question is always what saturated the original pool.

## Cloud Infrastructure

### 5. Cost-aware architecture: tearing down a cloud bill — Jitin Bahri
https://medium.com/@jitinbahri/cost-aware-architecture-tearing-down-a-cloud-bill-2196b772fb24

A line-by-line teardown of where cloud money actually leaks: idle environments running 24/7, requests far above usage, NAT and cross-AZ transfer charges, storage that never expires. The fix it argues for is architectural — cost visible and owned like latency — not a one-off cost-cutting sprint.

## Applied AI/RAG

### 6. RAG in Production: Retrieval Is Data Engineering, Not a Prompt Trick — André Claudino
https://medium.com/@andrelgcclaudino/rag-in-production-retrieval-is-data-engineering-not-a-prompt-trick-d07c3defe223

Answer quality can never exceed retrieval quality, so the piece reframes RAG as a data pipeline: measure Recall@K and ranking before touching prompts, keep a living 50-200 case golden set, and treat production failures as new eval cases. Includes a real ~77% LLM cost cut from retrieval-driven routing to smaller models.

### 7. Trying to Break My Own RAG Pipeline: Fault Injection, Confidence Gating, and the 150-Query Holdout Test — SG Reflections
https://medium.com/@saharh6683/trying-to-break-my-own-rag-pipeline-fault-injection-confidence-gating-and-the-150-query-holdout-baed64e97ea1

Instead of another success story, this one stress-tests a fail-closed RAG system with 11 fault injections and a fresh 150-query holdout set designed to break it — including an expired 2024 waiver checked against a Nov 2026 reference date. Retrieval accuracy dropped 40.9 points on the hard lexical set, and the system refused to answer rather than hallucinate. A model for how to actually validate a RAG pipeline before it meets users.
