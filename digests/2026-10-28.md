# Engineering Digest — 2026-10-28

Seven reads on why the fix is rarely more threads, more servers, or a bigger model. The theme of the day: **measure before scaling**.

## Distributed Systems

### 1. Engineering Lessons from Building Large-Scale Distributed Systems — Charu Taneja
https://medium.com/@charutaneja02/engineering-lessons-from-building-large-scale-distributed-systems-2af857d3abbb

Precomputed read models and two-query patterns beat expensive aggregations and giant joins once data grows. A practical reminder that the cheapest scale win is often doing less work per request, not adding capacity.

### 2. Bridging Systems Theory and Production Platform Engineering — Ram Mehta
https://rammehta1899.github.io/blog/2026/10/02/bridging-distributed-systems-theory-and-production-platform-engineering/

Raft, CRDTs, and snapshots each buy a different kind of safety at a different operational cost, and the failures live in the edges like heartbeat timing versus network jitter. Useful for matching a primitive to a workload instead of picking one on principle.

## Java / Spring Boot

### 3. Spring Boot in Production: Five Habits for a Service That Behaves — Makara SENG
https://medium.com/@makara.seng/spring-boot-in-production-five-habits-for-a-service-that-behaves-ca8d6b3f828e

Validated typed configuration, edge validation, one RFC 9457 error format, and ready-before-the-first-incident observability close the gaps that make an otherwise correct service hard to run. A checklist worth applying before the next on-call page, with Spring Boot 4 notes included.

### 4. Spring Boot Memory Leaks in Production: Why Your JVM Keeps Growing Until Kubernetes Kills It — Software Engineering Review
https://medium.com/engineering-playbook/spring-boot-memory-leaks-in-production-why-your-jvm-keeps-growing-until-kubernetes-kills-it-cf321dcfcd20

Raising the container limit only bought time because the leak lived outside the heap, in threads, direct buffers, and retained objects. The lesson: separate heap, process, and container memory before touching any limit.

### 5. Java 21 Virtual Threads Are Not Making Your Spring Boot Application Faster. Here's Why. — Systems at Scale & Java
https://medium.com/engineering-playbook/java-21-virtual-threads-are-not-making-your-spring-boot-application-faster-heres-why-68fbac05b261

Virtual threads make concurrency cheaper, not queries, HTTP calls, or CPU work faster, so services bottlenecked elsewhere see little gain. Read this before treating a thread-model switch as a performance fix.

## Applied AI / RAG

### 6. Why AI Agents Are Rediscovering Grep: The Limits of Vector RAG in Real-World Engineering — John Mandos
https://medium.com/@JohnMandos/why-ai-agents-are-rediscovering-grep-the-limits-of-vector-rag-in-real-world-engineering-b396b0d88df8

For debugging and code work, agents need exact facts more than semantically similar passages, so deterministic tools like ripgrep often beat elaborate vector retrieval. Argues for splitting the job: probabilistic models for reasoning, deterministic tools for facts.

### 7. Building a Production RAG Pipeline: From a Fake Chatbot to a Verified, Resilient AI Assistant — i.gooner168
https://medium.com/@i.gooner168/building-a-production-rag-pipeline-from-a-fake-chatbot-to-a-verified-resilient-ai-assistant-1c89dce279c4

Replacing keyword matching with real retrieval was only half the build; the production bugs surfaced under real traffic, and the fix was timeouts, a tested fallback, and failure testing instead of assuming it worked. A grounded end-to-end RAG build story.
